# خطة: إضافة ASP.NET Core Identity كخيار مصادقة ثالث في الـ template

## الملخص

إضافة `Identity` كخيار ثالث في معامل `AuthProvider` (بجانب `None` و `Keycloak`)، يولّد نظام مصادقة محلي كامل قائم على ASP.NET Core Identity + EF Core + JWT Bearer، مع `AuthFeature` جاهز (login/register/refresh/logout). يتبع نفس النمط المعماري المتبع في Keycloak: معامل `template.json` → رمز `DefineConstants` → `#if` → `PackageReference` مشروطة.

---

## القرارات المعتمدة (من إجاباتك)

| القرار | الاختيار |
|--------|---------|
| نوع Identity | Identity + EF Core (محلي) مع JWT Bearer |
| نطاق Endpoints | بنية تحتية + endpoints كاملة (AuthFeature) |
| DbContext | دمج في `AppDbContext` (يرث من `IdentityDbContext`) |
| DB Providers | دعم الـ 3 (PostgreSQL/SqlServer/Sqlite) — تلقائي عبر حزمة Identity.EntityFrameworkCore الواحدة |

## الملفات الجديدة (تحت `templates/vsa-webapi/`)

### 1. `Models/JwtSettings.cs` (gated `#if AUTH_IDENTITY`)
إعدادات JWT المحلية المُصدِرة للتوكنز:
```csharp
#if AUTH_IDENTITY
namespace VsaTemplate.Models;

public sealed class JwtSettings
{
    public string Issuer { get; init; } = "";
    public string Audience { get; init; } = "";
    public string SecretKey { get; init; } = "";
    public int AccessTokenExpirationMinutes { get; init; } = 15;
    public int RefreshTokenExpirationDays { get; init; } = 7;
}
#endif
```

### 2. `Data/Entities/ApplicationUser.cs` (gated `#if AUTH_IDENTITY`)
كيان المستخدم — يستخدم `Guid` key للاتساق مع `BaseEntity.Id`:
```csharp
#if AUTH_IDENTITY
using Microsoft.AspNetCore.Identity;

namespace VsaTemplate.Data.Entities;

public sealed class ApplicationUser : IdentityUser<Guid>
{
    public string? FullName { get; set; }
}
#endif
```

### 3. `Data/Entities/RefreshToken.cs` (gated `#if AUTH_IDENTITY`)
كيان refresh token مخزّن في DB (random string، لا JWT طويل العمر) — يرث `BaseEntity` للاتساق مع نمط soft-delete/audit:
```csharp
#if AUTH_IDENTITY
using VsaTemplate.Data.Common;

namespace VsaTemplate.Data.Entities;

public sealed class RefreshToken : BaseEntity
{
    public Guid UserId { get; set; }
    public string Token { get; set; } = "";
    public DateTime ExpiresAt { get; set; }
    public DateTime? RevokedAt { get; set; }
    public bool IsExpired => DateTime.UtcNow >= ExpiresAt;
    public bool IsActive => RevokedAt == null && !IsExpired;
}
#endif
```

### 4. `Data/Configuration/RefreshTokenConfiguration.cs` (gated `#if AUTH_IDENTITY`)
EF config لـ `RefreshToken` (فهرس على `Token`، علاقة مع `ApplicationUser`).

### 5. `Extensions/IdentityExtensions.cs` (gated `#if AUTH_IDENTITY`)
نظير `AuthExtensions.cs` لكن للهوية المحلية. يضمن:
- `AddIdentityAuthentication(JwtSettings, IHostEnvironment)` — يسجّل:
  - `AddIdentity<ApplicationUser, IdentityRole<Guid>>()` مع EF stores و token providers
  - `AddAuthentication(JwtBearer)` بـ `TokenValidationParameters` محلية (Issuer/Audience/SigningKey من `JwtSettings.SecretKey`، `ClockSkew=Zero`، `MapInboundClaims=false`)
  - `AddAuthorizationBuilder()`
  - نفس `JwtBearerEvents` التشخيصية في Keycloak (X-Auth headers في Dev، فحص `sub`)
- **Claims متوافقة مع `AuthClaims`**: يصدر JWT بـ `sub`=`user.Id`, `email`=`user.Email`, `preferred_username`=`user.UserName`, `name`=`user.FullName`, `roles`. هذا يضمن أن `CurrentUserExtensions` يعمل كما هو دون تعديل.

### 6. `Infrastructure/Authentication/ITokenService.cs` + `TokenService.cs` (gated `#if AUTH_IDENTITY`)
```csharp
public interface ITokenService
{
    (string accessToken, string refreshToken) GenerateTokens(ApplicationUser user, IList<string> roles);
    ClaimsPrincipal? GetPrincipalFromExpiredToken(string token);
}
```
`TokenService` يبني JWT بـ `JwtSecurityTokenHandler` + `SymmetricSecurityKey` من `JwtSettings.SecretKey`، ويولّد refresh token كـ random string (32 byte base64url) يُخزَّن في DB عبر `AppDbContext`.

### 7. `Features/AuthFeature/` — أربعة slices كاملة (gated `#if AUTH_IDENTITY`)

لكل slice: `Request/Response` record + `Command` + `Endpoint` + `Handler` + `Validator` (حيث ينطبق)، بنفس نمط `SampleFeature`:

| Slice | Route | الوصف |
|-------|-------|------|
| `Login/` | `POST /api/auth/login` | يأخذ email+password، يتحقق عبر `SignInManager`, يصدر tokens |
| `Register/` | `POST /api/auth/register` | يأخذ email+password+fullName، ينشئ مستخدم عبر `UserManager`, يصدر tokens |
| `Refresh/` | `POST /api/auth/refresh` | يأخذ refreshToken منتهي الصلاحية + refresh token صالح، يصدر جديد |
| `Logout/` | `POST /api/auth/logout` | يبطل (revoke) refresh token الحالي من DB |

كل endpoints تستخدم `[WolverinePost]` و `IMessageBus.InvokeAsync` كنمط `SampleFeature`. الاستجابة بـ `Response<AuthResponse>` حيث `AuthResponse` يحوي `AccessToken`, `RefreshToken`, `ExpiresIn`.

## الملفات المعدّلة (تحت `templates/vsa-webapi/`)

### 8. `.template.config/template.json`
- إضافة `"Identity"` كخيار ثالث في `AuthProvider.choices`
- إضافة رمز محسوب جديد:
  ```json
  "AUTH_IDENTITY": {
    "type": "computed",
    "value": "(AuthProvider == \"Identity\")"
  }
  ```

### 9. `.template.config/ide.host.json`
- إضافة خيار `Identity` في قسم `AuthProvider.choices` مع تسمية "ASP.NET Core Identity" ووصف "Local Identity with JWT Bearer authentication."

### 10. `VsaTemplate.csproj`
- إضافة `DefineConstants` لـ `AUTH_IDENTITY`:
  ```xml
  <PropertyGroup Condition="'$(AuthProvider)' == 'Identity'">
    <DefineConstants>$(DefineConstants);AUTH_IDENTITY</DefineConstants>
  </PropertyGroup>
  ```
- إضافة `PackageReference` مشروطة:
  ```xml
  <ItemGroup Condition="'$(AuthProvider)' == 'Identity'">
    <PackageReference Include="Microsoft.AspNetCore.Identity.EntityFrameworkCore" />
    <PackageReference Include="Microsoft.AspNetCore.Authentication.JwtBearer" />
  </ItemGroup>
  ```
  (JwtBearer مطلوب لـ Identity+JWT أيضاً؛ يبقى مشروطاً لـ Keycloak منفصلاً كما هو)

### 11. `Directory.Packages.props`
- إضافة تحت قسم `<!-- Auth -->`:
  ```xml
  <PackageVersion Include="Microsoft.AspNetCore.Identity.EntityFrameworkCore" Version="10.0.0" />
  ```

### 12. `Program.cs` — تعديلات بـ `#if`:
- **استيراد**: `#if AUTH_IDENTITY using VsaTemplate.Models; #endif` (قد يدمج مع كتلة Keycloak الموجودة)
- **ربط الإعدادات** (بعد الكتلة `#if AUTH_KEYCLOAK` الموجودة):
  ```csharp
  #if AUTH_IDENTITY
  var jwtSettings = builder.Configuration
      .GetSection("Jwt")
      .Get<JwtSettings>() ?? throw new InvalidOperationException("Jwt configuration section is missing or invalid.");
  #endif
  ```
- **تسجيل الخدمة** (خطوة 11): إضافة كتلة `#if AUTH_IDENTITY` تستدعي `AddIdentityAuthentication(jwtSettings, builder.Environment)`
- **OpenAPI security scheme**: تعميم الشروط من `#if AUTH_KEYCLOAK` إلى `#if (AUTH_KEYCLOAK || AUTH_IDENTITY)` في كتلتَي Swagger و Scalar، مع تغيير لاحقة العنوان من `" - Keycloak"` إلى شرطي (`" - Keycloak"` / `" - Identity"`)
- **Middleware**: تعميم `UseAuthentication`/`UseAuthorization` من `#if AUTH_KEYCLOAK` إلى `#if (AUTH_KEYCLOAK || AUTH_IDENTITY)`

### 13. `Data/AppDbContext.cs`
- تغيير التوقيع الشرطي:
  ```csharp
  #if AUTH_IDENTITY
  public class AppDbContext(DbContextOptions<AppDbContext> options)
      : IdentityDbContext<ApplicationUser, IdentityRole<Guid>, Guid>(options)
  #else
  public class AppDbContext(DbContextOptions<AppDbContext> options) : DbContext(options)
  #endif
  ```
- استدعاء `base.OnModelCreating(modelBuilder)` داخل `OnModelCreating` تحت `#if AUTH_IDENTITY` (قبل `ApplyConfigurationsFromAssembly`) لضمان تسجيل كيانات Identity
- إضافة `DbSet<RefreshToken> RefreshTokens` تحت `#if AUTH_IDENTITY`

### 14. `Models/CurrentUser.cs` + `Extensions/CurrentUserExtensions.cs`
- تعميم الـ gate من `#if AUTH_KEYCLOAK` إلى `#if (AUTH_KEYCLOAK || AUTH_IDENTITY)` في كلا الملفين — لأن claims متطابقة (sub/email/preferred_username/roles) بفضل `TokenService` الذي يصدر نفس أسماء الـ claims. لا حاجة لتعديل المنطق الداخلي.

### 15. `appsettings.json` + `appsettings.Development.json`
- إضافة قسم `Jwt` (مشروطة حسب الاختيار عبر `template.json` switch symbol `JwtSettings`، أو ببساطة ترك القسم دائماً كـ placeholder مثل `Keycloak`):
  ```json
  "Jwt": {
    "Issuer": "https://localhost:5001",
    "Audience": "vsa-webapi",
    "SecretKey": "CHANGE_ME_this_is_a_minimum_32_character_secret_key_for_dev_only",
    "AccessTokenExpirationMinutes": 15,
    "RefreshTokenExpirationDays": 7
  }
  ```
  > ملاحظة أمان: `SecretKey` placeholder للتطوير فقط؛ سيُوثَّق في README ضرورة تغييره في Production عبر secret manager.

### 16. `Extensions/GlobalExceptionHandler.cs` — لا تعديل
`UnauthorizedAccessException` → 401 و `ForbiddenException` → 403 موجودان مسبقاً ويعملان مع Identity.

## ملاحظات تقنية مهمة

- **لا حزم Identity خاصة لكل مزود DB**: `Microsoft.AspNetCore.Identity.EntityFrameworkCore` (v10.0.0) حزمة واحدة تعمل فوق Npgsql/SqlServer/Sqlite بدون أي حزم إضافية. "دعم الـ 3 مزودين" يتحقق تلقائياً ويُتحقَّق منه عبر الـ test suite.
- **claims متطابقة**: `TokenService` يصدر JWT بنفس أسماء claims المستخدمة في Keycloak (`sub`/`email`/`preferred_username`/`roles`)، مما يجعل `CurrentUserExtensions` و `AuthClaims` يعملان دون أي تعديل منطقي — فقط تعميم الـ `#if` gate.
- **`MapInboundClaims = false`** يُستخدم في Identity أيضاً للحفاظ على أسماء claims الخام (نفس نهج Keycloak).
- **ApplicationUser يستخدم `Guid` key** للاتساق مع `BaseEntity.Id` (Guid).
- **Refresh tokens تُخزَّن في DB** (random string، لا JWT طويل العمر) — أكثر أماناً ويتيمن الإبطال عند logout.
- لا يتم لمس `AuthClaims.cs` (يُولّد دائماً، يحتوي ثوابت تُستخدم في كلا المسارين).
