# Roadmap

This roadmap is intentionally short. It describes maintenance priorities rather
than promising dates. Priorities may change based on security reports, .NET and
dependency releases, contributor feedback, and evidence from real projects.

## Now: reliability and security

- Expand representative coverage across the 72-option project-template space and
  add Linux CI to catch path and platform differences.
- Strengthen Identity guidance and defaults around endpoint authorization, role
  seeding, role-assignment failures, lockout, and refresh-token retention.
- Complete the optimistic-concurrency example from request contract through an
  intentional conflict response.
- Add explicit reverse-proxy and forwarded-header guidance for IP-based rate limits.
- Keep package dependencies and generated framework guidance current with supported
  .NET and Wolverine releases.

## Next: contributor and release operations

- Add generated-application integration tests for representative create, query,
  validation, authentication, and authorization flows.
- Automate dependency-impact review and release verification without merging or
  publishing unreviewed changes.
- Maintain clearer release notes and an upgrade guide for projects generated by an
  older template version.
- Add issue and pull-request templates that capture affected template options and
  reproduction commands.

## Later: adoption evidence and developer experience

- Publish small reference projects for common database and authentication choices.
- Document public projects and case studies that use the templates, with permission.
- Evaluate an option to omit the sample feature and other focused community requests
  when they preserve the project's scope.
- Improve IDE discovery and cross-platform installation guidance.

## Non-goals

- Claiming that generated applications are production-complete without a
  deployment-specific review.
- Supporting every database, identity provider, architectural style, or hosting
  platform.
- Replacing application-specific authorization, domain modeling, threat modeling,
  or operational testing.
- Introducing options without sustainable verification and documentation coverage.

Suggestions are welcome through
[GitHub Issues](https://github.com/SaadAlsaree/net-vertical-slice/issues). Please read
[CONTRIBUTING.md](CONTRIBUTING.md) before proposing a substantial change.
